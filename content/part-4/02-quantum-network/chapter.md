# 从 QKD 到量子网络：密钥分发与一次性密码本

上一章我们用 BB84 换出了一把"防窃听的密钥"。有了密钥，怎么用它加密消息？答案是经典的 **一次性密码本（One-Time Pad, OTP）**——它和 QKD 是天作之合：**OTP 需要"超长且不能复用"的随机密钥，而 QKD 恰好能不断安全地供应密钥。** 这一章把它们拼起来，并看一眼"量子网络"这个更大的图景。

## 一次性密码本：最古老也最完美

- 加密：`密文 = 明文 ⊕ 密钥`（逐位异或）。
- 解密：`明文 = 密文 ⊕ 密钥`。
- 要求：**密钥长度 ≥ 明文长度，且每个密钥位只用一次。**

> 为什么完美？因为密文里的每个字节都只是"一个真随机数与明文异或"的结果——对攻击者来说，它看起来和纯随机没有两样，**数学上绝对不可破解**（可不破，但要保密密钥）。这就是"无条件安全"。

## 它唯一的痛点，正是 QKD 的长处

OTP 完美的代价是"密钥又长又得新鲜"——总不能每传一条消息都背着厚厚密钥本跑一趟。经典密码学因此很少真用 OTP（密钥配送成本太高）。但 QKD 改变了游戏：

- **QKD 在一条信任信道之外，用物理手段不断安全地"长出新密钥"**。
- 于是可以：**"QKD 产生新密钥 → 用于 OTP 加密每条消息"。** 
- 只要密钥是真随机、每次新、每次短新鲜，安全性就是物理级无条件的——不依赖任何数学难题。

> 组合拳：**QKD(供应密钥) + OTP(贴身加密) = 传输层无条件安全。** 这是 QKD 教学里最经典的闭环。

## 从"点到点"到"量子网络"

现实世界里 Alice 和 Bob 通常不相邻。真正的商用量子网络要考虑：

- **信任中继（Trusted Node）**：中间节点各自持有密钥，逐跳拼接端点密钥。简单但中间节点必须是可信的"中继站"（它能看到明文）。
- **量子中继（Quantum Repeater）**：用纠缠交换/纠缠纯化把量子态传得更远，避免"信任中继"的明文瓶颈——更安全但技术上更难。
- **量子路由器/交换机**：管理量子信道、基声明、密钥缓存，调度多条路径。

> 目前落地多按"信任中继 + 每跳 QKD"演进：银行、政务、科研网已试点（如北京-上海量子干线）。真正的"纠缠交换全网量子网络"仍在实验室到城域网的推进中。

## PQC 与 QKD：双轨还是二选一？

两者常被并列，但其实是**互补两件事**：

| | PQC | QKD |
|---|-----|-----|
| 靠什么 | **数学难题**（软件可升级） | **物理不可克隆**（需硬件） |
| 安全模型 | 假设难题难（计算安全） | 物理定律（无条件安全，防窃听） |
| 成本/部署 | 低，可现有协议热升级 | 高，需专用光路/单光子 |
| 长短板 | 抗 Shor/Grover，但怕"假设被攻破" | 防窃听一流，但需配认证防 MITM |

> 业界主流"混合异构"：**PQC 算法做身份认证 +  QKD 做密钥分发**——PQC 管"你是谁"，QKD 管"密钥不被看"。两者拼接成一个更有韧性的体系，这是第 5 篇综合实战要搭的东西的前置。

## 边界提示

本章是"系统性综述"，没有可运行示例（QKD 实物需光子硬件，OTP 你早已在 BB84 那节用过异或的思想）。你要带走的主线是：**密钥分发(QKD)解决"怎么安全地拿到对称密钥"，OTP 解决"拿到后怎么无条件加密"，量子网络解决"怎么把单条 QKD 扩展成成体系的中继网络"。** 这三层拼起来，就是连接经典世界与量子安全的最后一环。
