# 混合加密 TLS：X25519 + Kyber 双保险

现在把全书的知识串到真实世界里最常出现的地方：**TLS 握手**。如今业界在"经典 + 后量子"过渡期的稳妥做法，就是**混合密钥封装（Hybrid KEM）**——同时跑一条经典算法（X25519）和一条后量子算法（Kyber），把两者的共享秘密**拼接起来一起派生会话密钥**。这样两头都安全：不懂量子的旧端也能用（X25519 兼容），面对未来的量子机能抗（Kyber 兜底）。

> 直觉：**一把锁怕撬锁，就上两把不同原理的锁。** 攻击者必须两把都破才拿得到钥匙；而两把锁一个是"经典离散对数"、一个是"格难题"，量子只擅长撬其中一把（离散对数），另一把（格）它没辙。这就是双保险的意义。

## 关键概念：KEM（密钥封装机制）

在谈混合前，先认识 **KEM（Key Encapsulation Mechanism）**：

- **封装（Encapsulate）**：Bob 生成"密钥对"，公开公钥；然后用 Alice 的公钥"封装"出一个一次性会话密钥 `ss` 和对应的密文 `ct`。
- **解封（Decapsulate）**：Alice 用她的私钥解开 `ct`，得到同一个 `ss`。
- 这样双方不用发送 `ss` 本身，只交换公钥和密文——窃听者拿到公钥与密文也推不出 `ss`。

> 特性：**X25519** 是一种经典 KEM（基于曲线离散对数）；**Kyber（ML-KEM）** 是一种后量子 KEM（基于格/LWE）。防窃听的关键都在于"从公钥→私钥→ss"这条推理链对攻击者极难。

## 混合的要诀：拼接共享秘密

单跑一种都怕单一失效（经典怕量子，量子怕工程假设）。混合的做法是**两条并行**：

```
  经典通道: X25519 → ss_classic
  量子通道: Kyber   → ss_pq
  → 会话密钥 = KDF( ss_classic || ss_pq )   （按规范拼接后派生）
```

- 只要**两条里至少一条是安全的**，最终密钥就安全（经典密钥可加解密、量子密钥可加解密，但会话密钥由两者共同决定）。
- 即使未来某条被彻底破解，另一条仍保护会话密钥 —— **安全性取"两条中较强的"**，而不是"最弱的一环"。

> 打开右侧代码：我们用**纯 Python 的迷你混合 KEM**演示这个原理——不引真实 X25519/Kyber,而是抽象出两个"通道"，一条模拟经典(离散对数)、一条模拟格/Kyber。先分别算各自的共享秘密，再把两者拼接、派生出一个统一的会话密钥，并验证**只要任意一条通道的困难假设成立，攻击者就无法从公开信息推出最终密钥**。通过对比"单通道被破""混合下单通道被破"两种情形,亲眼看到双保险的价值。

## 为什么这是现实中的"现在完成时"

- **NIST 已发布 ML-KEM(Kyber)、ML-DSA、SLH-DSA 标准**（FIPS 203/204/205），迁移不再是"要不要"，而是"什么时候"。
- **TLS 1.3 已支持混合密钥交换实验扩展**，浏览器/服务器/CDN(如 Chrome、Cloudflare)开始灰度混合会话。
- "**先囤后破（harvest-now-decrypt-later）**"让今天必须护住密钥 —— 混合部署是降低"现在就被囤走、未来被解密"风险的最直接手段。

## 边界提示

本章用简化抽象演示**混合 KEM 的结构**（两条通道并行 + 拼接派生），不是真实 X25519/Kyber 的实现（真实参数字段、CCA 安全、认证与 TLS 语义远超本书范围）。你带走的结论：**过渡期的标准姿势 = "经典 + 后量子"并行，会话密钥由两者拼接派生；只要一条仍强，整体就安全。** 这为最后收官章的"对抗量子加密信"提供了密钥底座。
